# 1.0.1 — complete stop itineraries and a cleaner planner

The requested planner uses one ordered location card: start, numbered intermediate stops and destination. Every row has a three-line drag handle and a transparent map button. The standalone swap/search/bookmark buttons and selected-place preview/save row were removed. Dragging any row changes its position and preserves the location data; start/destination can become stops and vice versa. The planner's enclosing scroll view pauses during a drag; native accessibility increment/decrement actions provide an alternative. No new production dependency was added.

Address search runs after one second without typing, cancels outdated responses, and shows a loading indicator. Tapping a field browses Saved Places; typing a saved name filters them. Choosing one uses its name and coordinates. Map selection uses the nearest saved place within the existing 75 m tolerance for start, destination and intermediate stops, preserving the exact picked coordinate. A delayed blur callback cannot hide a newly focused field after inserting a row.

Joined legs now retain intermediate stops as named waypoint maneuvers (sign 5) in their correct geometry order. Only the final destination is a final arrival. Stop maneuvers appear in the normal turn cards, upcoming directions, speech and Live Activity stop icon. MapKit, native MapLibre and web MapLibre show numbered intermediate pins above the route. Library cards list every stop, retain metadata on save/open and preview its pins. Previously saved itineraries with waypoint metadata but missing stop instructions are repaired on read without changing the stored record; the repair is idempotent. Routes without stop metadata cannot reconstruct missing information.

The patch version is 1.0.1; binary tag v1.0.1, while AltSource remains the mutable 1.0 container. The previous 1.0.0 workflow was already cancelled before this patch; its pinned tag is not reused. All commits remain unsigned, and all native compilation remains on GitHub runners.

Validation: 216 JavaScript tests pass, including leg joining/stop guidance, old itinerary repair, moving endpoints with their coordinates/current-location state, saved-place matching and existing route/recording behavior. Lint and TypeScript checks pass. Headless Chrome exercised a one-second address debounce (one request), saved-place selection, dragging start past an intermediate stop to become destination, absence of the swap button, opening a saved itinerary with stops in Library/directions/map, and resolving a map click to a nearby saved Home. Public Milan fixtures and isolated browser storage were used; no user records or physical scooter were accessed. Native iOS/Android touch gestures and screen safe areas still require an installed build test. No local native compile or SDK download occurred.

References: [Apple's ordered stop planner](https://support.apple.com/guide/iphone/change-or-add-stops-to-your-route-iph837d13d03/ios), [React Native PanResponder](https://reactnative.dev/docs/panresponder).

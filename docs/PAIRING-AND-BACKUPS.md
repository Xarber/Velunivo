# Paired devices and file backups (1.0.4)

Settings → Data transfer separates File export and Device Connection. File backups contain the portable Library/garage/preferences schema and raw ride samples. They exclude Bluetooth credentials, map-provider keys and the permanent pairing secret. Saved backups are chunked, dated, independently downloadable/deletable and capped at 64 MB combined. Import offers merge or explicitly confirmed replacement. Existing records keep stable IDs.

Device Connection uses the existing one-use eight-character code flow. Once connected, Pair this device requires the other device's acceptance. Only the configured private PeerServer permits permanent pairing. A public-service outage fallback can still support an ordinary non-sensitive transfer, but cannot establish permanent pairing or move credentials.

The association has a 64-byte cryptographically random secret. SecureStore stores it in native apps; web uses the existing local-origin storage boundary. Persistent role-specific peer IDs are derived from SHA-256, and payloads are encrypted/authenticated with AES-GCM, fresh nonces, role/origin checks and bounded replay rejection. The secret is not put in a link or backup. Same-origin scripts can access web storage; permanent web pairing does not protect against a compromised app origin. OS Bluetooth chooser grants and platform bonding are not transferred.

The root transport is outside the refreshable app store. It reconnects at startup/foreground and checks every 30 seconds while active. Only one paired counterpart is admitted. Automatic import pauses during navigation/recording. Collections merge by stable ID and timestamped content revisions, with a deterministic hash tie-break. New/renamed items converge; deletions stay local and presentation preferences remain device-local. Private Bluetooth associations and provider keys are included only over the private paired session. An outage pauses automatic syncing instead of moving secrets through PeerJS Cloud.

Unpair requires both devices online and the other device's consent. A completion exchange clears both stored associations. An interrupted request before consent preserves the association and can be retried after reconnecting. This is not a distributed revocation service: catastrophic storage loss/network loss in the final completion exchange remains a failure scenario, and should not be advertised as impossible.

Validation used two isolated headless Chrome contexts with public QA saved places and the repository PeerServer. Pair/approve, initial merge, rename propagation without duplicates, reload recovery, interruption before unpair acceptance, fresh unpair approval, both-key removal and backup create/download/delete passed. Separate import UI checks verified merge and replacement confirmation. No real credential/user record was used. Core crypto tests cover tamper/replay/wrong-role/origin failures and merge conflict/idempotence. Native/native and native/web pairing still need installed-device validation. A continuously suspended app is not promised to execute background timers.

## Next update: recovery and settings

The original device-local preference rule above is superseded for device sync. Every edited global navigation/language/Bluetooth setting now carries its own persisted edit timestamp and configured marker. Missing defaults do not override configured choices; explicit newer changes, including a return to a default, win. Equal timestamps use deterministic values. Older non-default preferences migrate as configured with timestamp zero; old explicit defaults cannot be reconstructed. Settings metadata commits atomically alongside imported collections, with rollback. Private map-key edits also preserve edit times, including explicit deletion; key metadata/value stays outside file backups and public sync.

Paired devices now exchange small encrypted heartbeats independently of full exports/imports, ignore unknown control packets, expire a stuck transfer, show progress and expose Sync now/Reconnect without clearing the secret. Unconfirmed pairing can be retried through a new one-use code; confirmed pairing still requires both devices to approve unpair. The code owner arbitrates simultaneous pairing offers. Native WebView origin matching tolerates its legitimate root URL without a trailing slash, and its inline document source is memoized.

A completed unchanged comparison now reports “up to date” instead of leaving the UI waiting. Browser pair/merge/rename/reload/unpair and backup checks pass. Separate newer-settings/manual-reconnect checks are recorded in the validation notes. Actual native-to-native device synchronization remains unverified until the rebuilt apps are tested.

Canonical sync digests sort nested object keys by a deterministic code-point order. Property insertion order after import previously made identical preferences/private metadata look changed, causing repeated automatic transfers. Arrays still preserve their order, and real value changes still alter the digest. Entity revision hashes use the same canonical representation.

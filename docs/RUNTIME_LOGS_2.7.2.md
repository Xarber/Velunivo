# Release-build runtime diagnostics

Normal testing binaries now record console warnings/errors (including Expo errors surfaced through JS), fatal JS exceptions, browser errors/rejections, and Hermes release-mode unhandled rejections. The original console/error handlers continue to run. Development-mode Hermes keeps React Native's own rejection tracker; its console output is captured instead of replacing its UI behavior.

Recording still requires Developer Mode + Record debug logs. A small redacted in-memory ring retains up to 40 early warnings/errors until stored preferences load; it is discarded if logging is off and is never written without opt-in. Console volume, nested/circular values and stack sizes are bounded. Error events request an immediate asynchronous flush; abrupt OS termination can still preempt it. No logger can guarantee capture of native process crashes before JS starts.

Verbose diagnostics is separate, defaults false (including migrated preferences), and requires recording. It adds console info/debug/log, read-only Xiaomi telemetry responses, normalized bridge samples, recognized discovery metadata, and exposed native BLE services/characteristic flags. Writes only log queue metadata, never authentication payloads. No extra service-inspection I/O occurs when verbose is off. All entries use the existing launch sessions, seven-day retention, chunked persistence and single ZIP export. Recordings/telemetry analytics remain separate app data; logs do not duplicate GPS traces or media.

The source-only Animate Expo pass found the common indeterminate button progress sweep still using core Animated. It now uses a UI-thread Reanimated transform, no per-frame React state, pauses in background and stops for Reduce Motion. No new decorative screen/tab animations were added. Target feel remains for manual testing; neither a development client nor a Simulator certifies low-end release performance.

During the stopped development-client session, lazy split loading caused unknown-module errors. Metro was restarted with its supported EXPO_NO_METRO_LAZY setting; the dev script now includes it. The normal testing build embeds its JS and does not require Metro. Keychain entitlement errors were also observed in re-signed installed clients; no credential storage was downgraded to plaintext to hide those errors.

Validation: 500 JS/core tests and 54 Python workflow checks pass; Expo lint, TypeScript and whitespace checks pass. Runtime tests cover opt-in startup buffering, original handler preservation, release rejection callbacks, regular/verbose filtering, rate limits, redaction, circular/accessor inputs and failing sinks. The test checklist is in TESTING_2.7.2.md. Device Hub was quit while preserving the user's Simulator; subsequent checks were code-only.
